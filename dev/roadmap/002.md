Description
--------------------------

Currently the core classes are using two functions to multiply and divide units: _mul_units and _div_units. These functions basically, take the unit strings and create an equivalent unit string. Then, when a Var or Array is created, then the Unit class is called and a _translate_to_base method is used. This is not the best approach. The best approach is to once a Unit is created, then it uses the base representation (base_factor and base_exps) for any unit multiplication and division. New methods should be created in the Unit class to handle multiplication and division of units directly.
That is the easy part though. Due to the way the software was developed, when Var and Array classes interact with unit conversions, the unit strings play a way more important role than the base representation. This proposal aims to change that situation by the way the Var and Array classes handle units. They should handle only Unit classes. In concrete terms: core/var.py and core/array.py should only import Unit from antupy.core.units (currently it imports Unit, _assign_unit, _conv_temp, _mul_units, _div_units). All the internal transformations should be done by the Unit class and using the base representation.

Changes
------------------

1. The Unit class should implement the multiplication and division operations (`__mul__`, `__truediv__`, etc.). It already has a `__mul__` that needs to be tested. These operations should use the base representation and return a Unit variable.
2. The Var class should import only the Unit class.
    a) The method _assign_unit should be replaced by a simple Unit(). For that, Unit should accept Unit as input too (see point 3).
    b) The _mul_units and _div_units can be easily converted to Unit multiplications.
3. Unit should accept as input str|Unit|None. Currently it only accepts str. None should be treated as non-dimensional "-".
4. Repeat step 2 with Array.
5. The Unit.label_unit attribute should be a property. Instead the Unit should have two attributes: _units_numerator and _units_denominator. Both are list of str. Then label_unit uses these two attributes and build an equivalent unit_label. This is the only part where the original _mul_units and _div_units will be used!
5. For Var, the `__format__` and `__repr__` methods should be updated.
